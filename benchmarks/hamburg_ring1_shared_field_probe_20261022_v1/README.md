# 汉堡同车跨两个字段：原生路线响应小试验

40 辆人工车安全完成了 80 次原生 E1 贡献。
每辆车先经过 LSA119 的 Z.12 或 Z.13，再经过 LSA535 的 Z.4，各一次。
这证明“一辆模型车只允许对应一个被观测字段”不是这些路线的必要限制。
较大需求下的残差、进入积压和真实车辆归属尚未验证。

## 已验证的路线与计数

使用已有路线 178、179、180、181，每条 10 辆。
入口均为既有主干道 `44532531`，出口为既有 `142944318` 或 `28665128#0`。
当前网络的汽车通行权限、官方转向对应和路口归属检查均通过。
这些检查以当前网络和路口归属为准，不等于现场几何或自然驾驶行为验证。
计划没有掉头、重复道路、重复物理路口或客户专用道路。
没有删除网络中的合法掉头。

保持当前网络、控制输入、车辆类型及三处车身保持。
只保留既有的第一个字段车道意图和原移动经过点，没有新增第二个字段的车道保持或经过点。
使用项目 SUMO/TraCI 1.27.1、0.1 秒步长、seed 104，人工请求为 100–256 秒，运行至 1800 秒。
静止检查仍为全体在途车辆 300 秒。

| 原生检查 | 数值 |
|---|---:|
| 请求 / 进入 / 到达 | 40 / 40 / 40 |
| 碰撞 / 传送 | 0 / 0 |
| 原生停车时间之和 | 0 s |
| 119 Z.12 贡献 | 20 |
| 119 Z.13 贡献 | 20 |
| 535 Z.4 贡献 | 40 |
| 总 E1 贡献 | 80 |
| 逐车字段签名与先后次序 | 40/40 通过 |

计数全部来自周期 E1 的 `nVehContrib`。瞬时 E1 身份与周期计数一致。
每辆车在每个指定字段恰好贡献一次。80 次贡献不是 80 辆独立车辆，也不是反复经过同一检测器。
两个字段之间的原生通过时间差为 123.086–478.310 秒，中位数 312.206 秒。
这是稀疏人工车流下的时间差，不能当成拥挤主窗中的固定延迟。

## 对后续需求模型的影响

当前较大候选假定每辆车只贡献一个字段，并生成 8640 辆模型车。真实计数不能直接识别这个独立车辆总数。
本试验给出了四条已原生检验的共享路线。后续可提出共享车辆的需求备选，保留全部真实字段与时段目标，再单独验证。
本次没有改变当前较大候选、减少其车辆或重新解释它的计数。
也没有证明较少车辆一定减少排队、获得零误差或代表真实 OD。

人工目标为 13 个字段在 0–1800 秒的聚合响应，不是 130 个真实十五分钟目标。
原始 [主窗目标](expected-counts.csv) 及父运行中的 40 个派生站点目标保持原样。
主窗结果仍见 [完整入口候选](../hamburg_ring1_primary_entry_full_20261022_v1/README.md)，其零误差目标未完成。
固定范围航拍及 NetEdit 图沿用相同网络的父报告。
