## 观察到的阻塞链

3682 秒，119 K2 已为绿灯，但 `GS_266199063` 对应通路为红灯。
其上游 `79014037#1` 长约 3.46 米，车头停在约 2.459 米处。
该车辆后方还有停在转弯内部的车辆，119 Z4 首车仍停在停车线前。
该首车的停车状态为零，也已没有后续经过点。

3688 秒，`GS_266199063` 转为绿灯，但更下游的 `1966837175` 为红灯，原首车仍未移动。
3755 秒，前方车辆已清空，但 119 K2 自身为红灯。
3772 秒，下一次 K2 放行中已有车辆通过。
完整原生状态见[五次观测](diagnostic-native/green-observations/)。

这些记录说明，不能只根据某一信号为绿或入口能进入，就认为该通路能持续放行。
本次没有找到等待关系中的循环。既不宣称已证明死锁，也不把未发现循环当作没有阻塞的证明。
它们也不证明上述 OSM 信号是重复控制，更不授权删除真实信号或道路。
现场控制域和实际时差仍需对应证据。

## 固定标称时制 A_nominal_OSM

另作一次明确的初始化对照，需求及驾驶规则完全不变。
把 58 个剩余 OSM 感应程序改为静态程序，沿用现有状态、名义时长、XML 相位顺序和时差。
保留全部 10 个原固定程序，包括官方 M2 程序和 Z15 的 K9 备选 A。
删除感应时长限制及条件跳转。源程序 `4532610442` 原有一次条件自循环，也改为按 XML 顺序执行。
没有新增绿灯组合，也没有按计数残差优化绿灯时长。

原生加载时核对到全部 68 个活动程序均为静态、周期均为 90 秒。
检查没有推进仿真时刻，见[安装观测](nominal-native/installed-programs.json)。
这只是可复查的控制假设，不是现场 SPaT 或真实控制方案的证明。

## 判断与复算资料

本轮入口分配和统一固定标称程序的试验，均未解决整体计数问题。
下一项控制设计应检查路口间时差与车辆通过时间的相容性，保留官方相位和安全间隔。
本次没有证明其他控制方案不可行，也没有建立零残差标定。

曾考虑删除车道引导经过点，但核对官方语义后撤销了该推测。
正经过点速度是速度上限，不是必须达到的最小速度。[SUMO 定义](https://sumo.dlr.de/docs/Definition_of_Vehicles%2C_Vehicle_Types%2C_and_Routes.html#waypoints)
