# 历史 README V1 的 40 项站点计数归零

**本结果只复现旧 V1 的站点进入记录去重指标。它不是十月场景 130 项原生 E1 `nVehContrib` 归零。**

当前代码在同一套历史输入上复现 MAE **0.15**。
固定车辆速度因子后，只调整四辆车的出发时间，得到 **MAE=0、最大绝对误差=0、40/40 项一致**。
最终原生运行有 5037 辆全部到达，运行中、等待进入、碰撞、传送及丢弃均为零，错误日志为空。
这是同一观测窗口内的诊断拟合，不证明真实 OD、独立预测或现场物理对应。

## 保持的场景与指标

历史观测日期为 **2026-07-11**，冻结网络有 144 条普通道路。
四个站点合计包含 13 个官方字段，对应 12 个仿真检测点，每站比较十个 900 秒时段。
计数按站点和时段对车辆进入记录去重，并对齐 1 秒仿真步的通知时间。
仿真比较窗口为 `[1800,10800)` 秒，完整运行到 24000 秒，种子为 23423。

网络、检测点、信号和原始观测均未改变。最终四项出发时间变化见 `demand-changes.json`：

| 车辆 | 原出发时间 / 秒 | 最终出发时间 / 秒 | 变化 / 秒 |
|---|---:|---:|---:|
| `sensor_schedule_930` | 3582.07 | 3585.07 | +3 |
| `sensor_schedule_1438` | 5382.63 | 5385.63 | +3 |
| `sensor_schedule_1941` | 5382.87 | 5396.87 | +14 |
| `sensor_schedule_3465` | 8026.90 | 8012.90 | -14 |

全部车辆及路线保留。车辆速度因子固定为原始原生复现实际产生的值。
项目 `.venv` 内的 SUMO 1.27.1 完成所有运行。实际路径、版本和二进制、源文件哈希见 `environment.json`。
旧、新代码三个核心模块的 Git blob 相同，见 `old-new-code-comparison.json`。

## 失败记录与有界分支

最初两次候选和随后十次候选都保留，最优仅到 MAE 0.05。
930 号车延后三秒，确实从通知时刻 3599 秒移到 3602 秒，但另两辆车跨入其他时段，误差总和从 2 增至 4。
`rejected-trial-002-attribution.json` 保留实际事件变化。

后续只从这个被拒绝的中间需求建立一个分支。
`branch-source/` 保留适配后的源、原始审计、拒绝审计及适配哈希，不把中间需求称为原始输入。
适配审计保留原窗口和三项限制，使用该中间状态实测的完整 40 行结果及输入哈希。
分支上限为十次候选、相对中间需求最多移动 117 秒。第四次候选已归零，因此停止。
分支四次候选的绝对误差总和依次为 6、4、2、0，所有失败均保留。
最终实际最大出发时间变化为 14 秒。

`native/` 冻结 22 次完整原生运行：最初两次搜索的四次运行、十次搜索的十二次运行、分支的六次运行。
每次都保留实际需求、瞬时检测记录、周期 E1、逐步汇总、全部行程、碰撞记录、命令和日志。
不变的网络和检测配置保存在 `inputs/`。
每次都包含完整 40 行进入记录去重结果，以及相同检测点下原生完整通过计数的对照。

| 保留结果 | 站点进入记录去重 MAE | 原生 `nVehContrib` 汇总 MAE |
|---|---:|---:|
| 原始 V1 复现 | 0.15 | 13.275 |
| 十次搜索最优 | 0.05 | 13.100 |
| 分支最终结果 | 0.00 | 12.825 |

这些原生完整通过计数仍不是十月场景的独立 130 项字段比较。
不得用本表切换验收指标，也不得用站点汇总掩盖字段残差。

## 保留的物理与信号限制

- LSA535 含两条诊断替代连接，并在原 120 秒信号方案中增加同向相位。官方信号组 2 和 7 未回放。
- 站点 35822 的 Z11/Z12 共用一个距入口 0.01 米的探针，所在仿真道路仅长 0.20 米。原字段坐标位于简化道路之外。
- 站点 26585 含一处低置信投影，继承自缺失的官方进口几何。

零误差不消除这些限制，不能据此称为完整物理数字孪生。
十月 236 道路、130 字段时段的正式标定仍是另一项未完成工作。
