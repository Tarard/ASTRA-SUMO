# 汉堡检测断面的局部车道保持试验

这是车道引导的小规模检验，**不是原观测窗的零误差标定结果**。
试验包含 130 辆车。每个原字段分配 10 辆，共 13 个试验计数目标。
这 130 辆试验车不等于正式标定要求的 130 个字段时段。
原 130 个真实字段时段和 40 个派生站点时段均保持原样，完整需求仍须单独验证。

## 结果

| 检查项 | 原局部途经点 | 只在车头通过前启动保持 | 覆盖车尾通过的保持 |
|---|---:|---:|---:|
| 进入 / 到达 | 130 / 129 | 130 / 130 | 130 / 130 |
| 通过指定字段的车辆 | 122 | 130 | 130 |
| 只通过其他字段的车辆 | 4 | 0 | 0 |
| 无完整字段通过记录 | 4 | 0 | 0 |
| 执行保持并恢复设置 | — | 125 | 130 |
| 碰撞 / 传送 | 0 / 0 | 0 / 0 | 0 / 0 |
| 原生瞬时与周期 E1 核对 | 一致 | 一致 | 一致 |

对照组剩余一辆车停在 `186821027#0_4`，等待声明中始终为红灯的 LSA535 转向 5。
它原应通过相邻车道上的 Z8。原生停止快照保留车道、信号、前车和让行关系，未发现候选等待循环。
此前完整运行中也有车辆完成正确车道上的移动途经点后，在计数断面前换入其他车道。

最终试验的全部 130 辆车各通过指定字段一次。13 行试验目标全部一致，MAE 和最大绝对误差均为 0。
全部车辆恢复原换道设置后到达，没有遗留保持状态，也没有未恢复就退出仿真的车辆。
恢复时刻逐车晚于原生 E1 记录的车尾通过时刻。详见 [独立核对](verified-probe-summary.json)。
这证明本次试验中的局部保持生效，不证明完整需求可行或自然驾驶行为正确。

## 已声明的驾驶方式

原生移动途经点负责让车辆选择目标字段的车道。
当车辆已在该车道，且车尾尚未通过检测位置时，临时使用 `laneChangeMode=512`。
该模式关闭自主换道，并保留碰撞避免与安全间距约束，参见 [SUMO 官方说明](https://sumo.dlr.de/docs/TraCI/Change_Vehicle_State.html#lane-change-mode-0xb6)。
车尾通过后恢复该车此前的换道设置。试验仅改变换道模式，没有车道移动、速度、位置、路线或信号指令。
控制依据是声明的车道意图和车辆位置，不使用检测器计数反馈。

原生步长和保持检查均为 0.1 秒。SUMO、TraCI 和 sumolib 均使用仓库环境中的 1.27.1。
网络、控制、道路权限和普通车辆参数沿用前次局部途经点候选。
车流每 2 秒交替出发，覆盖全部 13 个字段。计数目标为当地 07:30–07:45 每字段 10 辆。
仿真从当地 06:30 开始，结束于 08:00，seed 为 104。
试验目标是人工构造的检验车流，不是汉堡实测流量。

## 边界修正与取消记录

第一版只在车头尚未通过断面时启动保持。5 辆车在车头已越过断面、车尾仍未通过时才并入目标车道。
它们在小试验中计数正确，但没有执行保持。最终版本补上这段车身覆盖范围，130 辆车全部执行并恢复。
刚启动的第一版完整需求候选因此被主动停止。
[取消记录与原始输出](cancelled-full-front-only/) 保留停止原因、当时源码和不完整计数。
该次停止是实现边界修正，不是碰撞或容量失败，也不是正式完整时段结果。缺失时段保持缺失。
